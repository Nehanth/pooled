## A 177B model in a browser tab, faster with every device that joins

**PENDING (#368).** Pooled 2.0 runs **Qwen3.8-Flash-Next**, a 177B mixture-of-experts model (about 100 GB of files), in a Chrome tab on a Mac. The model doesn't fit in the Mac's memory, so the tab copies the experts into the browser's own storage once and reads the ones each token needs from the SSD. Then a gaming PC joins the room with `pooled join` and takes some of the layers, and the same answer comes out faster.

| Setup | Decode speed | Output |
|---|---|---|
| Mac, one Chrome tab, experts from the SSD | 7.0-8.5 tok/s | matches llama.cpp's greedy ids |
| Mac tab + RTX 5070 PC (`pooled join --gb 10 --ram 43 --disk`) | 10.8-12.3 tok/s | matches llama.cpp's greedy ids |

The speed panel (#353, #358, on `main`) shows live tok/s, each device, the time per hop and how often the expert cache hits.

Measured on #368's branch, not on `main` (Mac: Chrome 155 headless, Metal, the tab lending 20-24 GB; PC: a room node on the same LAN holding layers 14-47 with most of their experts parked in its RAM, not a tab). Three golden prompts per setup. The numbers are partly warm: no purge, and the Mac's page cache held some of the copy.

## What's new

### Models
- **Qwen3.8-Flash-Next** (`qwen3.8-flash`) [preview]: 512 experts with 10 active per token, hyper-connections, a per-layer n-gram table and QSA, on Pooled's own WebGPU engine. Greedy output matches llama.cpp. On `main` it is dev-gated (`POOLED_DEV=1` for the CLI, `?dev=1` on the page); a normal picker row is **PENDING (#370)**.
- **Qwen3.5 122B MoE** (`qwen3.5-122b-moe`): `pooled pull` / `list` / `host`, ~73 GB across the room. A Mac Studio plus an RTX 5070 PC keeping its experts in RAM runs it at ~17 tok/s. On the room page with `?dev=1`.
- Qwen3 1.7B opens at 16K context (8K when the room is short of memory); the 35B MoE goes up to 128K (`?ctx=131072`), the 27B up to 64K.
- The tokenizer uses Qwen's own pre-tokenizer split, checked against llama.cpp. Some token ids differ from 1.0; the new ones are correct.

### Experts in RAM and on SSD
- **`--ram N`**: on a discrete-GPU computer, `pooled host` / `pooled join` keep MoE experts in system RAM with a GPU cache. One RTX 5070 runs the 35B MoE alone at ~38-45 tok/s. On by default when the room's pledges are short; `--ram 0` turns it off. Never on unified memory.
- **`--disk`** (the 35B and 122B on `main`; Flash layers on a room node are **PENDING (#368)**, `main` refuses to offload them): when GPU and RAM still fall short, some layers' experts are read from the model files on the SSD, through a RAM cache and a disk-aware planner. Worker-thread reads get past Windows' ~2.6 GB/s single-handle ceiling.
- **The disk tier in a tab**: experts in OPFS, reader workers and a staging ring, bit-exact with resident. On `main` it is a bench page; in rooms it is **PENDING (#368)**.
- The per-layer offload cut in Chrome drops from 2.9 ms to 0.5 ms.
- Converted weights and prompt checkpoints are cached on disk, so a second load skips conversion, and OpenClaw's first answer after a restart drops from ~35-52 s to ~1.2 s on a two-node GB10 room (2.2 s solo, #313).

### Speed
- MoE prompt processing ~2x (GB10: 402 -> 861 tok/s at 2K); MoE plain decode in Chrome 55 -> 64 tok/s at 1K.
- DP4a prefill on by default on NVIDIA, for dense models (~1.8x on the 27B) and the MoE. Never on Apple.
- Room prompts go through the prefill kernels: OpenClaw's cold turn on two devices 196 s -> 51-64 s.
- Windows room nodes start in ~30 s instead of 200-290 s.

### Rooms and security
- 6-character room codes, and Allow / Deny for new devices (on by default).
- Channel-bound mutual auth: the invite key and passes are proved, never sent, and a mesh key covers every link.
- Every device checks who runs the model against the creator's roster; a member can no longer repoint the host.
- Rooms never use more memory than a device pledged. Pledges count at most 64 GB per device; for **Qwen3.8-Flash-Next only**, a computer lending from the terminal (`pooled host` / `pooled join`) counts up to 128 GB. A browser tab still lends at most 64 GB.
- A default TURN relay (pooled.run `/api/turn`), used by the CLI too, for networks where direct links fail.

### Terminal and API
- `@pooled/cli`: `pooled host`, `join`, `chat`, `pull` / `list` / `rm`, an interactive menu, and Windows support.
- **`pooled serve`**: a room as a local OpenAI Chat Completions / Responses and Anthropic Messages endpoint, with tool calling. Works with Codex CLI, Claude Code, opencode, Continue and Open WebUI.
- `@pooled/openclaw`: OpenClaw's gateway as a room device (0.3.2, on ClawHub and npm). 0.3.2 bundles the room node from October 8, so it doesn't have Flash, `--disk` or the CLI's TURN relay until a new plugin release.
- A docs site at [pooled.run/docs](https://pooled.run/docs).

## Compatibility and upgrading

- **The room protocol is unchanged (4).** 1.x and 2.0 tabs can share a room, with two limits: a 2.0 creator refuses a Start pressed on a v1.0.0 tab (reload it to press Start), and a v1.0.0 tab turned away with "this tab runs an older Pooled" (it happens when the host asks before new devices join, the default) only needs a reload.
- **Update your CLI to lend a GPU to Qwen3.8-Flash-Next.** Pooled 2.0 rooms need `@pooled/cli` **2.0.0** or newer for Flash, the SSD expert tier, the TURN relay and the safer Start rules: `npx @pooled/cli@latest join "<invite link>"`, or `npm i -g @pooled/cli@latest`. An older `pooled join` can still join a 2.0 room and run the smaller models, but a Flash start fails with "couldn't load its layers (unknown model qwen3.8-flash)". `pooled serve` / `pooled chat` 0.4.x keep working unchanged. *(The CLI version is a draft decision: 2.0.0 to match the product, or 0.5.0 on the CLI's own track.)*
- `pooled serve` can't use a v1.0.0 host (it has no API) and says so.
- **PENDING (decision): older devices must prove the invite link.** If the strict default lands in 2.0, hosts stop accepting the old unprotected invite key. Devices running `@pooled/cli` 0.3.6 or older, the OpenClaw plugin 0.2.3 or older, or a tab left open since before October 4 wait for the host to let them in, and can't hold layers until they update. Hosts that need the old behaviour for now: `?legacyauth=1` on the room page, `POOLED_LEGACY_AUTH=1` for `pooled host` and the plugin (flag naming not final). If the flip doesn't make 2.0, this paragraph becomes: legacy auth is still on, and turns off in 2.1.
- Behaviour changes to know about: the layer split defaults to "For speed"; MoE dp4a prefill is on by default on NVIDIA (`?dp4a=0`); `--ram` is on by default when a room is short; iPhone pledges are capped at 1 GB; scripts that join a gated room need the invite link or `--allow-all`.

## Known limits

- **The first answer takes seconds with experts on disk.** Prompts over offloaded layers are read one token at a time (2-5 s for a ~25-token prompt in #368's runs); batched prefill with offload isn't supported yet.
- **Qwen3.8-Flash-Next's context is capped at 2048 tokens in rooms** until long context lands (**PENDING**). QSA works past 2048 in the engine but isn't wired into rooms.
- **A one-time copy of up to ~92 GB** (**PENDING #368 / #370**; 92 GB is #370's picker figure, and #368's Mac test profile held ~93 GB). The first Flash load in a browser copies the offloaded layers' experts (all 48 layers for a Mac alone) and, on the device holding layer 1, the 28.8 GB n-gram table into the tab's storage (OPFS). That needs the free disk space and takes a while; later loads read nothing from the network. The consent prompt (**PENDING #368 / #370**) asks before it starts. Each browser origin and profile keeps its own copy.
- Flash's tab disk tier (**PENDING #368**) is tuned with modelled costs that aren't calibrated per device yet.
- In a room whose model host isn't the creator, `pooled serve` stays not-ready (503). Keep the device that started the room as the model host.
- Chrome or Edge on a laptop or desktop is the tested host. Firefox and Linux Chromium need WebGPU switched on.

## Research Pooled builds on

Pooled 2.0's disk tier and expert cache build on LLM in a flash (running from flash storage), on MoE offloading with a per-layer expert cache, and on Petals, WebLLM and EdgeShard for the room itself. Papers and how each one maps to Pooled: [README: Research Pooled builds on](../../README.md#research-pooled-builds-on).
