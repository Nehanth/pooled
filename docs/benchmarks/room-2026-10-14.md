# Qwen3 1.7B room measurements, 12–14 October 2026

These measurements exercise the #21 benchmark protocol on real browser, native and phone participants. They are historical observer-enabled deployment results, not a speedup claim or hardware validation of the current PR revision.

R = RTX 3090 / Windows Chrome; G1 and G2 = separate GTX 1060 6 GB / Linux Node/Dawn machines; S = physical S21 Ultra / Android Chrome. GPU work used LAN WebRTC; phone automation used USB. The requesting API guest serves no layers.

All rows use Qwen3 1.7B Q8, 16K context, the standard `hello`, `meaning`, `japan` prompts and a 400-token cap. Each series has one first request, three warm-ups and 15 measured requests. The table shows `meaning`; [JSON](room-2026-10-14.json) retains all 42 prompt/mode rows, spread, source identity, allocations, hashes and speculation counts.

## Identity and interpretation

Measured upstream base: `307344d18ace9e1bd621f32aed5d932ebf7658b9`, plus the benchmark patch fingerprint `0c7640431bc7b510948c90bb524625586249ef953da46612f5c98ba8e3714ed1`. Harness fingerprint: `59e82009917585535140a570e316fcaa97a0ed8573e1999cd2531303638c6a42`. GGUF SHA-256: `061b54daade076b5d3362dac252678d17da8c68f07560be70818cace6590cb1a`. The associated evidence records retain tokenizer/config revisions, hashes, runtime/backend versions and device limits.

The source fingerprint predates the identity-validation fix and rebase onto current main. Source fingerprints are SHA-256 of sorted `path NUL file-sha256 LF` entries. Old measurements are not relabelled as tests of the later source. The prepared PR evidence bundle contains full raw schedules for R plain, G1 plain and G1/S plain/defaults, and aggregate reports for all fourteen series. Its four raw-series reports reproduce byte-for-byte with the rebased reporter.

TTFT is measured on the requesting client; token delivery uses `(N-1)/(last-first)` and counts tokens sharing a text chunk at the same arrival time. These are distinct from host TTFT and upstream decode rate. Timing and resource observers are on. Earlier observer controls showed variable overhead; these values are not uninstrumented headline throughput. One-way network latency is not inferred from unsynchronised clocks.

Plain uses exact sampling with speculation disabled. Native defaults also use exact sampling, while browser defaults use creative sampling; the complete records retain the setting. Speculation was inactive in solo defaults, active in mixed meaning/Japan requests, and inactive in hello. There is no claim that all default-mode outputs should match plain.

Normal planner decisions are preserved separately from controlled allocations: G1/S uses a supported 5/1 GB pledge and 23/5 layers; G1/S/G2 uses 2.5/1/2.5 GB and 10/5/13 layers. Normal native allocations left S ask-only. R/G1 uses a controlled 18/10 split. Device order, not just device count, matters.

Modes ran sequentially with different starting temperatures. G1/S defaults reached Android thermal status 1; three-device runs remained at 0. Battery temperatures are not GPU temperatures. These are not thermally controlled A/B comparisons. Plain token equality and physical phone display agreement were audited; captured token IDs remain in the representative bundle.

## Coverage and limits

Fourteen completed series cover R, G1, G2, G1/G2, R/G1, G1/S and G1/S/G2 in both modes: 266 requests, 210 measured. Full schedules include first/warm-up requests. The representative raw subset has 76 requests, 60 measured. Failed setup attempts were retained separately and are not silently included as successful runs; this table is not a reliability pass-rate estimate.

Retained setup failures include certificate/phone-navigation and native-signaling failures, and two intermittent R/G1 default-start failures whose cause is unresolved. A separately labelled diagnostic pilot is excluded. S solo 1.7B is blocked by the normal memory budget. No CPU adapter or driver workaround is part of these measurements.

The owner is doing training runs on the RTX 3090 this week, so remaining in-depth RTX testing will lag. R/S, four-device generation, RTX/phone endurance and fresh representative hardware reproduction remain deferred. Earlier loading/overhead controls retain their own source identities and are not part of this generation table. This contribution does not complete the entire #21 roadmap or add its public `/bench` page.
