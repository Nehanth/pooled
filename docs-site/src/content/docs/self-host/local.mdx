Pooled is a static site: plain HTML and JavaScript modules, with no build step. Any static server works, as long as it applies two rewrites.

## Serve a checkout

```sh
git clone https://github.com/Nehanth/pooled && cd pooled
npx -y serve -l 8080 .
```

Open [http://localhost:8080/room](http://localhost:8080/room). `npm run serve` runs the same command.

`serve` reads `serve.json` for the rewrites:

```json title="serve.json"
{
  "rewrites": [
    { "source": "/room", "destination": "/p2p.html" },
    { "source": "/r/:code", "destination": "/p2p.html" }
  ]
}
```

Production uses the same two rewrites in `vercel.json`, so keep the two files in step.

:::caution[Don't open the HTML files directly]
Opening `p2p.html` from disk (`file://`) doesn't work. The room loads ES modules, and the landing page uses absolute `/site/...` paths. Serve the repository root.
:::

### Using another server

If you use nginx, Caddy or something else, map `/room` and `/r/<code>` to `/p2p.html`. For example, with Caddy:

```text title="Caddyfile"
:8080 {
  root * /path/to/pooled
  rewrite /room /p2p.html
  rewrite /r/* /p2p.html
  file_server
}
```

## Signaling

A local checkout uses the public PeerJS server by default, the same as pooled.run. That works from localhost. To keep everything on your machine, run a local PeerServer and point the room at it:

```sh
npx peer --port 9000 --path /
```

```text
http://localhost:8080/room?signal=127.0.0.1:9000
```

On an http page a bare `host:port` uses `ws://`. `?signal=` opens the room in dev mode; add `&dev=0` if you don't want that. Every device must use the same server. See [Signaling servers](/docs/self-host/signaling).

## What still comes from the internet

The page still loads PeerJS from `cdn.jsdelivr.net`, model files from Hugging Face (unless a device in the room has them), and STUN from Google's public servers. Browser caches are per site, so weights cached on pooled.run download again on your origin (and `localhost` and `127.0.0.1` are different sites).

## Other devices on your network

WebGPU needs a [secure context](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts). `http://localhost` counts; `http://192.168.1.20:8080` on another device does not, so that device gets no GPU and can only ask.

<Tabs>
  <TabItem label="Serve over https">
    Serve the checkout over https with a certificate the devices trust, for example Caddy with a real domain name. Then run the signaling server behind TLS too: an https page can only open `wss://`. See [Put it behind TLS](/docs/self-host/signaling#put-it-behind-tls).
  </TabItem>
  <TabItem label="Mix with pooled.run">
    Keep the computers on their own checkout at `http://127.0.0.1:8080/room`, and open `https://pooled.run/room` on phones. Use the public PeerJS server on every device (don't add `?signal=`), so they all meet on the same server.

    Run the same commit as pooled.run (`main`) so both speak the same room protocol.
  </TabItem>
  <TabItem label="Browser flag (home Wi-Fi)">
    On Chrome for desktop and Android (and Brave, at `brave://flags`), `chrome://flags/#unsafely-treat-insecure-origin-as-secure` lets you list `http://192.168.1.20:8080` as secure. Use it only on a network you trust. `npm run lan` serves the site and a signaling server for this and points the room's QR code at your computer: see [A room on your Wi-Fi](/docs/kits/home-wifi).
  </TabItem>
</Tabs>

## Code mode previews

Previews run on a second site so a runaway app can't freeze the room. Locally that is the other loopback name (`localhost` ↔ `127.0.0.1`), with nothing to set up. On a LAN address there is no second site, so previews run in the room's tab and `run_js` is off.
