Start the bridge with `npx @pooled/cli serve ABCD`. When the room's model is ready, the banner prints a Claude Code line with your room's numbers. Copy it, or build it yourself. This example is for a 32768-token room:

```bash
ANTHROPIC_BASE_URL=http://127.0.0.1:8080 ANTHROPIC_API_KEY=pooled \
  CLAUDE_CODE_MAX_CONTEXT_TOKENS=32768 CLAUDE_CODE_MAX_OUTPUT_TOKENS=8192 \
  CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 claude --model pooled
```

Run it in your project. Claude Code works as usual, with the room's model behind it.

## What each variable does

| Variable | Value | Why |
|---|---|---|
| `ANTHROPIC_BASE_URL` | `http://127.0.0.1:8080` | Sends Claude Code's requests to the bridge. No `/v1` at the end. |
| `ANTHROPIC_API_KEY` | `pooled`, or your token | Any value works without a token. With `POOLED_TOKEN` set, use the token. |
| `CLAUDE_CODE_MAX_CONTEXT_TOKENS` | the room's context | Claude Code does not know a model called `pooled`. Without this, it never compacts before the room refuses a prompt that is too long. |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS` | a quarter of the context, at most 32000 | Claude Code keeps its output limit (32000 by default) free in the window. On a room under about 32K, it would refuse its own prompt with "Prompt is too long" before sending anything. |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` | `1` | Stops side requests, such as session titles, from queuing between the agent's steps. Each one would make the room process the whole prompt again. |

For the values for each model, see [Context settings](/docs/serve/recipes#context-settings-for-coding-agents).

## Pick a room that can run Claude Code

Claude Code's prompt is 15,000 to 20,000 tokens before any history.

<Tabs>
  <TabItem label="35B MoE (best)">
    32K by default. Ask the host to open the room with `?ctx=65536` for 64K:

    ```bash
    ANTHROPIC_BASE_URL=http://127.0.0.1:8080 ANTHROPIC_API_KEY=pooled \
      CLAUDE_CODE_MAX_CONTEXT_TOKENS=65536 CLAUDE_CODE_MAX_OUTPUT_TOKENS=16384 \
      CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 claude --model pooled
    ```
  </TabItem>
  <TabItem label="27B">
    16K by default, which is too tight. Ask the host to open the room with `?ctx=32768`:

    ```bash
    ANTHROPIC_BASE_URL=http://127.0.0.1:8080 ANTHROPIC_API_KEY=pooled \
      CLAUDE_CODE_MAX_CONTEXT_TOKENS=32768 CLAUDE_CODE_MAX_OUTPUT_TOKENS=8192 \
      CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 claude --model pooled
    ```
  </TabItem>
  <TabItem label="1.7B (not recommended)">
    At most 16K, which leaves about 1,000 tokens after Claude Code's prompt. One file read can overflow it, and the 1.7B cannot write the compaction summary. Use a bigger model.
  </TabItem>
</Tabs>

## What to expect

- The first step processes Claude Code's whole prompt. Each step after that reuses the room's caches and processes only the new tool results.
- MCP servers work. A request can carry up to 1024 tools.
- Anthropic's own server tools (web search, bash, text editor and the like) are skipped with a logged warning.
- Thinking works. The thinking block's signature carries the reasoning, so when Claude Code sends the block back, the room gets its exact reasoning again.
- Pasted images become a short note (`[image omitted: this model reads text only]`), since the models read text only. The session keeps going.

<Aside type="caution" title='"Prompt is too long"'>
If Claude Code shows this before anything reaches the room, `CLAUDE_CODE_MAX_OUTPUT_TOKENS` is missing or too large for the room. If the room answers with a `400` saying the prompt is too long, `CLAUDE_CODE_MAX_CONTEXT_TOKENS` is missing or larger than the room's context. Check `ctx` in `curl http://127.0.0.1:8080/health`.
</Aside>

<Aside type="note">
Tested with Claude Code 2.1.285. On the Qwen3.6 35B MoE, `claude -p` read a file with its Read tool and answered with its contents in about a minute. The second step reused about 15,200 prompt tokens from the room's caches.
</Aside>
