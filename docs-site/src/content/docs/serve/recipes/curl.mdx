Start the bridge with `npx @pooled/cli serve ABCD`. Every example uses the default port, 8080.

## Check the room

```bash
curl http://127.0.0.1:8080/health
```

```json
{"ok":true,"room":"ABCD","connected":true,"ready":true,"model":"pooled/qwen3.6-35b-moe","ctx":32768,"queue":0,"served":12}
```

| Field | Meaning |
|---|---|
| `connected` | The bridge is connected to the room. |
| `ready` | The room's model is started. Until then, requests get `503` (`529` on Messages) with `Retry-After: 5`. |
| `model` | The room's model id. |
| `ctx` | The room's context, in tokens. Use it for the coding agents' [context settings](/docs/serve/recipes#context-settings-for-coding-agents). |
| `queue` | Requests waiting at the bridge, plus the one running. |
| `served` | Requests this bridge has served. |
| `closed` | Only present after the host disconnected this client: the reason. Requests then get `503`. |

`GET /v1/models` lists the model with `max_model_len` set to the room's context. `GET /` prints the bridge's banner, including the agent settings.

## Anthropic Messages

```bash
curl http://127.0.0.1:8080/v1/messages -H 'content-type: application/json' -H 'anthropic-version: 2023-06-01' \
  -d '{"model": "pooled", "max_tokens": 200, "messages": [{"role": "user", "content": "Hi"}]}'
```

Add `"stream": true` for server-sent events.

## Responses

```bash
curl http://127.0.0.1:8080/v1/responses -H 'content-type: application/json' \
  -d '{"model": "pooled", "input": "Hi"}'
```

The answer's `id` can go in `previous_response_id` on the next request, while the bridge is running.

## With a token

If the bridge was started with a token, send it on every request. Either header works:

```bash
curl http://127.0.0.1:8080/v1/chat/completions -H "Authorization: Bearer $POOLED_TOKEN" \
  -H 'content-type: application/json' -d '{"model": "pooled", "messages": [{"role": "user", "content": "Hi"}]}'

curl http://127.0.0.1:8080/v1/messages -H "x-api-key: $POOLED_TOKEN" -H 'anthropic-version: 2023-06-01' \
  -H 'content-type: application/json' -d '{"model": "pooled", "max_tokens": 200, "messages": [{"role": "user", "content": "Hi"}]}'
```

Without the token, `/health` answers only `{"ok": true}` and every other path answers `401`.

## Common errors

| Status | Cause | What to do |
|---|---|---|
| `400` | Unsupported feature, or the prompt is longer than the room's context | Read the message. Shorten the prompt, or ask the host for a longer context. |
| `401` | Missing or wrong key on a bridge with a token | Send the token. |
| `403` | The request had an `Origin` header or a foreign `Host` | Call from the same computer, not from a web page. |
| `429` / `529` | The queue is full, at the bridge or in the room | Wait and retry, or raise `--max-queue`. |
| `503` / `529` | The model is not started, the host is gone, the host disconnected this client, or the host pressed Stop | Wait for the host, then check `/health`. |
| `504` | The room sent nothing for 5 minutes (30 minutes while the host queues it) | Check the room's page for a stalled device. |
| `500` | Generation failed in the room | Retry. If it repeats, check the host's page. |

The OpenAI column comes first where the two differ. The full table is in [Limits and context](/docs/serve/limits).

<Aside type="note">
`/v1/embeddings`, the legacy `/v1/completions`, `/v1/responses/input_tokens`, `/v1/responses/compact` and `/v1/messages/count_tokens` are not served and return `404`.
</Aside>
