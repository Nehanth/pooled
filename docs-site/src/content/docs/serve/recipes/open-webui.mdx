<Steps>

1. Start the bridge. Open WebUI also uses port 8080 by default, so give the bridge another port:

   ```bash
   npx @pooled/cli serve ABCD --port 8081
   ```

2. In Open WebUI, open **Settings → Connections → OpenAI API** and add a connection:

   - **URL:** `http://127.0.0.1:8081/v1`
   - **Key:** any value, or your token if the bridge has one

3. Pick the room's model in the model menu. It is listed as `pooled/<model>`, for example `pooled/qwen3.6-35b-moe`.

</Steps>

## Open WebUI in Docker

The bridge listens on `127.0.0.1` only, and it refuses requests whose `Host` is not `127.0.0.1` or `localhost`. Inside a container, `127.0.0.1` is the container itself, so a normal Docker setup cannot reach the bridge. `host.docker.internal` does not work either.

Use one of these:

- Run Open WebUI directly on your computer, not in Docker.
- Run the container with `--network=host`, so it shares your computer's network. Then `http://127.0.0.1:8081/v1` works from inside it.

<Aside type="note">
The bridge only listens locally on purpose. It keeps other machines on your network, and web pages in your browser, from using the room through it. See [CLI options and security](/docs/serve/options).
</Aside>

## What to expect

- Chats from Open WebUI show in the room's chat marked "via API", under the room's visibility setting.
- Pasted images become a short note, since the models read text only.
- Open WebUI sends side requests of its own, such as chat titles. They wait in the room's queue like any other request.
