`pooled` is the command-line bridge from the `@pooled/cli` npm package. It has one command, `serve`. For setup and client recipes, see [Serve API](/docs/serve).

:::note[Coming: pooled chat, join and host]
`pooled chat`, `pooled join` and `pooled host` are in preview in [PR #270](https://github.com/Nehanth/pooled/pull/270), not on npm yet. See [Rooms from the terminal](/docs/terminal).
:::

## Install

It needs Node 22 or newer. No GPU is needed on this machine.

<Tabs>
<TabItem label="npx">
```bash
npx @pooled/cli serve ABCD
```
</TabItem>
<TabItem label="Global install">
```bash
npm install -g @pooled/cli
pooled serve ABCD
```
</TabItem>
<TabItem label="From the repo">
```bash
cd cli && npm install
node bin/pooled.js serve ABCD
```
</TabItem>
</Tabs>

## Synopsis

```text
pooled serve <ROOM CODE | room link> [options]
pooled --version
pooled --help
```

`serve` joins the room as an API client with no layers, then serves the room's model on `127.0.0.1` as OpenAI (Chat Completions and Responses) and Anthropic (Messages) endpoints.

The room argument is a code of 4 to 6 letters and digits, or a room link. From a link it takes `?code=`, then the last part of the path (`/r/ABCD`), then the hash (`#ABCD`).

## Options

| Flag | Default | What it does |
|---|---|---|
| `--port <n>` | `8080` | HTTP port on `127.0.0.1`. `0` picks a free port; the banner prints it. |
| `--token-file <f>` | none | Requires the token in this file on every request, as `Authorization: Bearer <t>` or `x-api-key: <t>`. |
| `--token <t>` | none | The same token, given on the command line. Other users on the computer can read it with `ps`, and `pooled` warns about it. |
| `--name <s>` | `pooled serve` + 4 random letters | How the room shows this client, up to 40 characters. The hostname is never used, since every guest sees this name. |
| `--signal <host:port>` | PeerJS cloud | Signaling server, the same one the room page uses with `?signal=`. |
| `--max-queue <n>` | `8` | Requests that may wait here behind the running one. More get `429` (OpenAI) or `529` (Anthropic). `0` accepts a request only when idle; a negative number counts as `0`. |
| `--quiet` | off | Prints only errors. |
| `--json-log` | off | One JSON object per log line: `{t, level, msg}`. |
| `-v`, `--version` | | Prints the version. |
| `-h`, `--help` | | Prints the help. |

### Tokens

Set a token in one of three ways. The first one found wins:

1. `--token-file <f>`
2. the `POOLED_TOKEN` environment variable
3. `--token <t>` (prints a warning about `ps` unless `--quiet`)

```bash
POOLED_TOKEN=$(openssl rand -hex 16) npx @pooled/cli serve ABCD
```

With a token, every path needs it except `GET /health`, which then answers only `{"ok": true}` to callers without it. Without a token any API key is accepted, because some tools insist on sending one.

:::caution[--signal takes host:port only]
The CLI's `--signal` is simpler than the room page's `?signal=`. It takes one `host:port`. The port defaults to 443, and the connection is secure only on port 443. It does not take a comma list or a `wss://` URL. Use the same server the room's host opened the room on.
:::

## What it prints

Once the room's model is ready, the banner shows the base URLs and settings for the coding agents, sized to the room's context:

```text
pooled serve · room ABCD · Qwen3.6 35B MoE · Q4 · 32768 tokens of context
  OpenAI     http://127.0.0.1:8080/v1         (OPENAI_BASE_URL, any API key: chat/completions, responses)
  Anthropic  http://127.0.0.1:8080            (ANTHROPIC_BASE_URL: messages)
  bound to 127.0.0.1 only · no token (set POOLED_TOKEN to require one)
  prompts go to the room's host and may be shown to everyone in the room
```

If the host has not started the model yet, the agent settings appear when it does, and again if the context changes. `GET /` on the running server returns a similar plain-text banner: the version, the paths each API serves, the `/health` URL and the same agent settings.

## Exit codes

| Code | When |
|---|---|
| `0` | `--version`, `--help`, `pooled` with no arguments, `pooled help`, or a clean stop with Ctrl-C or `SIGTERM`. |
| `1` | Node older than 22, the port is busy or cannot be bound, or joining the room failed (no such room within 15 s, the signaling server unreachable, or a host too old for API clients). |
| `2` | Bad arguments: an unknown command or flag, no or a malformed room code, a bad `--port`, a `--max-queue` that is not a number, an empty token, or an unreadable or empty `--token-file`. `--help` after a command (`pooled serve --help`) prints the help and also exits `2`. |

On Ctrl-C, open requests end with an error, the client leaves the room, and the process exits. A second Ctrl-C exits at once.

:::tip[Port 8080 is busy]
The repo's `npm run serve` also uses 8080. Pass `--port 8081` and change the base URLs to match.
:::

## Behaviour to know

- It listens on `127.0.0.1` only. Requests whose `Host` is not `127.0.0.1:<port>` or `localhost:<port>`, or that carry an `Origin` header, get `403`, so a web page cannot reach the room through your browser.
- At most 64 connections at once.
- One generation runs in the room at a time. The room's chat, Code mode and API clients share one queue.
- While a request waits, a stream gets a keep-alive every 10 s.
- If the host page reloads, in-flight requests fail and the client reconnects when the room is back. It knocks on the room's code every 3 s for a minute; after that it gives up, and requests get `503`. If the host disconnects the client or turns API clients off, the process keeps running but answers every request with `503`. Restart it to rejoin.
