**Goal:** an OpenClaw assistant that thinks with the Qwen3.6 35B MoE, running on your own computers.

[OpenClaw](https://github.com/openclaw/openclaw) is a self-hosted assistant. The Pooled plugin makes Pooled its model: the OpenClaw gateway starts a Pooled room and holds part of the model on its own GPU. Your other computers, browser tabs and phones join the room and hold the rest.

## You need

- **A computer with a GPU for the gateway:** Linux with Vulkan (glibc 2.38 or newer, like Ubuntu 24.04), or macOS 26 or newer. Windows is untested.
- **Node 22 or newer** and **OpenClaw 2026.9.6 or newer**.
- **About 23 GB of GPU memory across the room** for the 35B MoE, the model for OpenClaw. One big machine can hold it alone. This guide pools two devices.
- **A 20.8 GB download** for the MoE, once per machine, and **30 minutes** the first time.

## Steps

<Steps>

1. **Install the plugin** from ClawHub:

   ```bash
   openclaw plugins install clawhub:@pooled/openclaw
   ```

   OpenClaw shows ClawHub's security audit, then the plugin's capabilities, and asks before each. Answer `y` to both. The ClawHub listing is new. The same package is on npm: `openclaw plugins install @pooled/openclaw`.

   <Shot src={install} alt="ClawHub Security Audit for @pooled/openclaw 0.2.0: Outcome Safe, then Proceed with installation?" />

2. **Pick Pooled.** Run `openclaw onboard`. Under **Model/auth provider**, choose **More…** and type `pooled`.

   <Shot src={provider} alt="The provider search: pooled, 1 match, Pooled (Your own devices, no API key)" />

3. **Start a room on this device.**

   <Shot src={start} alt="How should this device take part? Start a room on this device, or Join a room" />

4. **Lend memory and pick the MoE.** Say how much of this GPU's memory to lend. The model list marks **Qwen3.6 35B MoE** as recommended for OpenClaw and says whether it is downloaded. If it isn't, onboarding offers to download it now, when the gateway starts, or not at all.

   <Shot src={model} alt="Lend 16 GB, then the model list: Qwen3.6 35B MoE, downloaded, needs about 22.8 GB, recommended for OpenClaw" />

   Then keep **Two (this + one more)** devices and **Devices with the invite link**. Onboarding prints the room code and the invite link. They stay the same when the gateway restarts. Answer the rest of onboarding as you like.

   <Shot src={room} alt="The Pooled room box: room code GX4-BAC, the invite link, and how another device joins" caption="The invite key is hidden in these captures." />

5. **Start the gateway**, if onboarding didn't: `openclaw gateway run`. The room opens with it, in about 10 seconds.

6. **Add a second device.** On another computer (or a second terminal), run `pooled join` with the invite link, or open the link in Chrome or Safari. See [Rooms from the terminal](/docs/kits/terminal). With the invite link it gets in at once. With the code alone, it waits for you:

   <Shot src={join} alt="pooled join with the code alone: waiting for the host to let this device in" />

   Open a chat with `openclaw tui` and type `/pooled`. It lists who waits. `/pooled allow` lets them in:

   <Shot src={allow} alt="/pooled lists spark-join wants to join (computer, 10 GB); /pooled allow answers Let in: spark-join" />

   The model loads once the room holds it (48 seconds in our test). `/pooled` then says **online** and which layers each device holds:

   <Shot src={online} alt="/pooled: qwen3.6-35b-moe online, 26 GB pledged, layers 0-23 and 24-39" />

7. **Give it a first task.** Put a `notes.txt` in OpenClaw's workspace and ask:

   ```text
   Read notes.txt in my workspace and turn it into a to-do list, most urgent first.
   ```

   It reads the file with its `read` tool and answers.

   <Shot src={task} alt="The TUI: /pooled shows the room online, then the task and a to-do list grouped by urgency" />

   `openclaw dashboard` opens the same chat in the Control UI, with the tool call and the model, **Qwen3.6 35B MoE · Pooled room**:

   <Shot src={controlUi} alt="The Control UI: Read notes.txt, the to-do list, and Qwen3.6 35B MoE · Pooled room GX4-BAC under the message box" />

</Steps>

## What you should see

- **The first answer is slow: about 3 minutes in our test.** OpenClaw sends a prompt of about 18,000 tokens (its instructions and tools), and the room reads it once. That took 150 seconds here.
- **Later answers are fast.** The room keeps that prompt, so the next question took 14 seconds, and the same task in a new session took 46 seconds. After a gateway restart, the plugin reads the prompt again as soon as the room is online, before you ask.
- Our test ran both devices on one GB10. On two computers the times differ with their GPUs.

Every device that holds layers sees the conversation, including the files OpenClaw reads, and could steer its tool calls: share the invite link only with people you trust. See [Who can see and steer what](/docs/openclaw#who-can-see-and-steer-what).

## If something goes wrong

### The chat says the room "is waiting for devices" or is short of memory
The room doesn't have the devices it waits for, or their pledges don't hold the model yet. `/pooled` says how many GB it is short. Add a device (step 6), lend more with `/pooled pledge <GB>`, or pick a smaller model with `openclaw onboard`. A question waits up to 120 seconds for the room before it gives up.

### A device waits to join
It came with the code, not the invite link. `/pooled` shows who waits, `/pooled allow` lets the first one in and `/pooled deny` turns it away. `/pooled link` prints the invite link to send instead.

### `Gateway not detected`
Onboarding couldn't start the gateway as a service. Run `openclaw gateway run` and keep it open.

### `No WebGPU adapter` or the gateway can't use the GPU
The plugin needs Vulkan on Linux or Metal on macOS 26 or newer. If the optional WebGPU package didn't install, the gateway says how to add it.

More: [OpenClaw](/docs/openclaw) and [Troubleshooting](/docs/troubleshooting).
