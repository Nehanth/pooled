The roadmap lives in the repository, in [`roadmap/README.md`](https://github.com/Nehanth/pooled/blob/main/roadmap/README.md). It lists every planned item, grouped by the part of Pooled it touches: Kernels, Inference, Harness (Code mode), Loading, Networking, Room, UI, Infra, and Tests and benchmarks. Longer design notes sit next to it as numbered files, such as `roadmap/02-prefill-gemm.md`. The pinned [Roadmap: Pooled](https://github.com/Nehanth/pooled/issues/83) issue has the same list as a checklist.

## Priorities

| Priority | Meaning |
|---|---|
| **P0** | Now. Broken, wrong, or the biggest thing holding rooms back. |
| **P1** | Next. Planned and ready to build. |
| **P2** | Later, or needs a design note first. |

A filed issue gets the `area:` label of its section. Design-note file names never change, because issues and links point at them.

## Top of the list

- **Prefill speed** (P0, [#2](https://github.com/Nehanth/pooled/issues/2)). Prefill is the biggest gap against native llama.cpp. On one GB10, the first token of a 172-token prompt takes about 1.0 s on the MoE, against about 0.07 s natively.
- **Split MoE rooms that end answers mid-call** (P0, [#68](https://github.com/Nehanth/pooled/issues/68)). A two- or three-device MoE room must match a single device.
- **Coop GEMV with 8 rows per workgroup** returns wrong values (P0, [#47](https://github.com/Nehanth/pooled/issues/47)).
- **Hand the host role to another device** when the host leaves (P1, [#58](https://github.com/Nehanth/pooled/issues/58)).
- **Pinned model revisions and weight hashes** (P1, [#19](https://github.com/Nehanth/pooled/issues/19)), so an upstream re-upload can't mix old and new ranges.

## Pick something up

1. Find an item in the roadmap and read its design note, if it has one.
2. Comment on its issue before you start, so two people don't build the same thing.
3. P2 items and anything that changes the protocol, the model output or what peers can see need a design note first. See [Contributing](/docs/contributing#changes-that-need-a-design-note-first).

Benchmark reports from hardware we don't have help every item on the list. See [Benchmarking](/docs/contributing/benchmarks#report-numbers-from-your-hardware).
