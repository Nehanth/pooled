A template is a small app that already runs. You start with working files and ask for a change, like "add a pricing section". Small models do much better editing a working file than writing a whole app from nothing, so a template is the best start on a small model like Qwen3 1.7B.

## Start from a template

<Steps>

1. In Code, press **New** above the file list.

2. Pick a template from the menu next to the name box, for example **Start from: Game**. It fills in the project name; type your own if you like.

3. Press Enter. The project gets the template's files and is served on `:5173` straight away, so the app is running in Preview.

4. On the host, the prompt box already holds a first change to try. Send it, or write your own. (A project started from another device gets no suggestion in the box: ask for a change yourself.)

</Steps>

Anyone who can send requests can start a project from a template. The host creates it.

## The four templates

| Template | What it is | Suggested first change |
|---|---|---|
| **Game** | Catch the falling stars on a canvas. Move the basket with the arrow keys, the mouse or a finger. Score and 3 lives. | Add a high score that stays after a reload |
| **Dashboard** | Stat cards, a bar chart drawn on a canvas, and a table, all from one `DATA` array of six months. | Add a line for sign-ups to the chart |
| **Form app** | A sign-up form that checks its fields and adds each entry to a saved list. | Add a phone number field and a search box over the list |
| **Landing page** | A hero, three features and an email sign-up box, with a menu button on small screens. | Add a pricing section with three plans |

Each one is three files: `index.html`, `style.css` and `app.js`, a single JS module. Every file is under 50 lines, well under the roughly 100 lines the agent writes at once. None of them uses the network.

:::note[Saved data in the preview]
The Form app and "a high score that stays after a reload" use `localStorage`. In the preview it lives in memory only, so it is empty again after the preview reloads. The code is right: it keeps its data once the project's files run outside the preview, for example the **Project .zip** on your own web server. The **One HTML file** download keeps the preview's in-memory storage, so it forgets too. See [Previews](/docs/code/previews#what-an-app-can-do-in-the-sandbox).
:::

## Built for the sandbox

The templates avoid what the preview sandbox blocks. The Form app and Landing page have no `<form>` submit, since the frame has no `allow-forms` and a submit event never fires. A button click and the Enter key do the work instead. The Game stops the arrow keys and Space from scrolling the page while you play.

If you ask the agent to add a form, the same rule applies: ask for a button that handles the click, not a submit.

## Empty project

**Empty project** is the default in the menu. The agent starts with no files and writes everything, in parts of about 100 lines per file. A bigger model and a bigger context help here: see [The agent](/docs/code/agent#context-and-compaction).
