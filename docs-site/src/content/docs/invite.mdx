Every device you add brings the memory it gives. More memory lets the room run a bigger model.

## Send the invite

In the room, press **Invite** in the header, or click the room code next to the logo. The **Invite a device** sheet shows three ways in:

- **A QR code.** On a phone, scan it with the camera app.
- **The room code**, four characters, to type on the other device. Codes never use I, L, O, U, 0 or 1, so they are hard to misread.
- **A link** like `https://pooled.run/r/K7QX`, with **Copy link**. On devices that support it, **Share…** opens the system share sheet.

:::note[Coming soon (PR #268)]
Room codes become six characters, shown as `4TK-G9P` (four-character codes of older rooms keep working), and the host decides who gets in:

- A device with the **invite link** or QR code (it carries the room's key after `#k=`) comes in at once.
- A device that types the **code alone** waits until the host presses **Allow** or **Deny** in a prompt under the header. **Room settings → Joining → Ask before new devices join** (on by default) turns this off.

This is in [PR #268](https://github.com/Nehanth/pooled/pull/268), which isn't merged yet. Today codes are four characters and anyone with the code can join.
:::

The same QR code, code and **Copy link** button are also beside the model picker, under **Invite more devices**, with a **Full-size QR** button.

## Join from the other device

<Tabs>
  <TabItem label="Link or QR">
    Open the link, or scan the QR code. The page checks the device and joins the room by itself, with a generated name and this device's default memory. Change the memory afterwards under **This device gives**.
  </TabItem>
  <TabItem label="Room code">
    Open [pooled.run/room](https://pooled.run/room). Set the name and **Memory**, type the four characters under **Have a code?** and press **Join**.
  </TabItem>
</Tabs>

**Memory** (on the join screen) and **This device gives** (in the room) set what this device gives the room. Phones and tablets have a cap. See [Phones and tablets](/docs/phones).

A device without WebGPU shows **Chat only, no memory to give**. It can still join, ask questions and read the answers.

## While it connects

The join screen says what it is doing: `Connecting…`, then `Reaching the other devices…`. If it takes longer, you see one of these:

| Message | What to do |
|---|---|
| `Still connecting…` | Wait a few more seconds. |
| `No room with that code.` | Check the code, and that the page of whoever opened the room is still open. |
| `Found the room, but these two devices can't reach each other` | A strict firewall or mobile network blocks the direct path, and no relay helped. Put both devices on the same Wi-Fi, try another network, or add a relay under **Network**. See [Rooms at work](/docs/rooms/at-work#when-it-still-fails). |

pooled.run gives every room a TURN relay, so devices on work networks that block direct connections still get in. See [Rooms at work](/docs/rooms/at-work). The **Network** box under the join form takes a relay of your own instead. The setting is saved in this browser only and never goes into join links. See [TURN relay](/docs/self-host/turn).

## What a lending device shows

A device that gives memory can open the **Serve API** page from the header to see what it is doing:

| Status | Meaning |
|---|---|
| **Standing by** | Waiting for the room to start a model. |
| **Loading 42%** | Downloading and loading its layers. |
| **Serving** | Holding layers, for example `Layers 1–20 · 2.4 GB · Qwen3.6 35B MoE`. |
| **Not holding layers** | The other devices run the model, and this one joins to ask. |
| **Host reconnecting** | The host's tab closed. The room waits a minute in case it comes back. |
| **Room over** | The host left. Press **Start a new room** to lend this device again. |

While it loads or holds layers, it also warns you about what can stop it:

- the tab was in the background, where passes can stall;
- the screen can go to sleep (set Auto-Lock to Never on an iPhone, or the screen timeout to its longest);
- the device is not charging, or the battery is low.

:::tip
A sun icon shows in the header while this device holds layers. Lit, it means Pooled is keeping the screen on; as a warning, it means the screen may sleep and drop out of the room.
:::

## When a device leaves

If a device that holds layers leaves or stops answering, the room says so and the host can deal its layers out again with one click (**Re-deal the layers**). With **Re-deal on its own** (on by default, experimental), the host does it by itself when the device is not back within a minute. A device that comes back after a reload rejoins under the same name. See [Device drops and recovery](/docs/rooms/recovery).

Not every device gets layers. By default the room splits **For speed**: the fastest devices hold the layers and the rest join to ask. See [How layers are split](/docs/rooms/split).
